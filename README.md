# Prime Care Hospital Management System

Android app (Capacitor 6.2.2) for Prime Care Hospital, with its data online: an API on Render backed by MongoDB Atlas.
Doctors and managers sign in to register staff; staff run the OP token desk; patients book their own tokens.

## Project layout

| Path | What it is |
|------|------------|
| `www/index.html` | App shell: launch animation, screen, sheet and toast containers |
| `www/styles.css` | Design system (brand colours from the Orbit Cross logo) |
| `www/app.js` | Screens, server connection and sync, accounts, staff registration, OP tokens |
| `www/config.js` | The server address the app connects to (`apiUrl`) |
| `server/` | The Prime Care API (Node 20, Express, MongoDB driver) |
| `render.yaml` | Render Blueprint that deploys `server/` |
| `www/vendor/` | Capacitor core and plugin bundles (no internet or bundler needed) |
| `android/` | Native Android project generated by Capacitor |

## Data (online)

All data lives in MongoDB Atlas (database `primecare`), behind the API in `server/`. The app works online only:
without a connection it shows "Can't reach Prime Care" with a Try again button.

- **Sign-in and passwords** are checked on the server. Passwords are stored as bcrypt hashes and never sent to phones.
  Sessions last 30 days and renew while in use. Changing or resetting a password signs that account out on other phones.
- **What each phone gets:** doctors, managers and staff get every record. Patients get only their own account and
  visits, plus an anonymous view of today's queue (token number, status, doctor) for the "Now consulting" board.
- **Sync:** every record has a revision number (`rev`). Phones ask for changes since the revision they already have,
  every 15 seconds and on pull-to-refresh, and every change answers with the latest changes too.
- **IDs and token numbers** are handed out by the server, so two phones can never issue the same one.
  Accounts `PCA-01`, staff `PCS-0001`, patients `PCP-00001`.
  OP tokens: `ddmmyy-NNN`, the date (in `HOSPITAL_TZ`, India by default) plus that day's running count, e.g. `151026-007`.
  Numbers are never reused, even after a cancellation. A mobile number holds one active token per day.
- **Forgot password** (no SMS yet): hospital accounts verify with username + registered phone; patients with
  mobile/Patient ID + date of birth.
- **Backup:** Settings → Data → Download backup (doctors and managers) saves all records, without passwords, as JSON.
  Erase all data deletes everything on the server for every phone, after the password is typed again.

After every saved change a line sweeps across the top of the screen: green = added, orange = updated, red = deleted/cancelled.

## Going online: GitHub, MongoDB Atlas and Render

1. **GitHub:** create an empty repository named `prime-care` and push this folder to it (APKs, `node_modules`
   and `.env` files are ignored).
2. **MongoDB Atlas** (free M0 cluster): create a project `Prime Care` and a free cluster. Under Database Access add a
   user with a strong password. Under Network Access allow `0.0.0.0/0` (Render's free plan has no fixed IP address).
   Copy the connection string from Connect → Drivers.
3. **Render:** New → Blueprint → choose the `prime-care` repository. Render reads `render.yaml`, creates the
   `prime-care-api` web service and generates `JWT_SECRET`. Paste the Atlas connection string as `MONGODB_URI`.
   When it is live, `https://<service>.onrender.com/api/health` answers `{"ok":true}`.
4. **App:** put the service address in `www/config.js` (`apiUrl`), then build the APK. The first doctor or manager
   to open the app creates the hospital's first account.

Render's free plan sleeps after 15 minutes without requests; the first request after that takes up to a minute,
and the app shows "Connecting to the Prime Care server…" meanwhile.

To run the API on your computer: copy `server/.env.example` to `server/.env`, fill it in, then
`cd server && npm install && npm run dev`.

## Reports (PDF)

`www/reports.js` builds A4 PDFs with jsPDF 2.5.2 + AutoTable 3.8.4 (bundled in `www/vendor/`). Every page has the
logo header, report title, period and report ID, a thin page border, and a "Page X of Y" footer. Files are saved to
`Documents/PrimeCare/Reports` and opened with `@capacitor-community/file-opener`.

Reports: OP Token Register, Daily OP Summary, Doctor-wise Consultations, OP Fee Collection, Cancelled Tokens,
Patient Accounts, Staff Directory, and (for patients) My Visit History. Periods: today, yesterday,
this week, last 7 days, this month, last month, last 30 days, this year, all time, or a custom range.

## Native plugin, sounds and search

- `android/app/src/main/java/com/primecare/hms/BiometricPlugin.java` is an in-app Capacitor plugin
  (`PrimeBiometric`, registered in `MainActivity`) wrapping AndroidX BiometricPrompt. Settings → Security turns on
  fingerprint unlock for one account per phone; the app then locks on launch and after a minute in the background.
- `www/features.js` holds the sound effects (Web Audio tones, all under a second, switchable in Settings), the
  fingerprint lock screen, and the global search (top-bar magnifier) across tokens, staff and patients.

## Token slips and WhatsApp

- `www/tokens.js`: printable OP token (PDF and on-screen) with logo, token number, date, time, patient, doctor, visit,
  fee, vitals and status inside a thin border. Saved to `Documents/PrimeCare/Tokens`.
- `WhatsAppPlugin.java` (`PrimeWhatsApp`): opens the patient's WhatsApp chat directly with the token PDF attached
  (no share sheet or contact picker); the user taps Send in WhatsApp.

## Roles

| Role | Can do |
|------|--------|
| Doctor | Everything a manager can; sees the day's OP tokens with a date picker for history, starts/completes consultations, writes notes |
| Manager | Registers staff (and gives them app sign-in) and doctor/manager accounts; views OP tokens by date; cancels tokens |
| Staff | Signs in only if a manager enabled it; issues and edits OP tokens for today |
| Patient | Registers on the Patient Login page (gets a Patient ID like `PCP-00001`), signs in with mobile number or Patient ID, books one OP token for today, sees visit history with doctor's notes |

## Build the APK

Requires Node, JDK 17 and the Android SDK (API 34).

```sh
npm install
npm run build:apk
```

The debug APK is written to `android/app/build/outputs/apk/debug/app-debug.apk`.
